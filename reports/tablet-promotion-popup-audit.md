# 태블릿 프로모션 팝업 점검

## 초기 측정 상태

통합 브라우저는 홈의 초기 로딩 문구만 반환한 뒤 후속 검사 시 사용할 수 없었고, 독립 브라우저에서는 개발 서버 문서가 반복적으로 교체되는 동안 React 루트가 마운트되기 전에 측정이 종료되었습니다. 이 상태에서는 팝업의 실제 기하나 로컬 스토리지 지속성을 신뢰성 있게 판정할 수 없으므로, 로컬 프로덕션 번들과 독립 브라우저로 대체 검증을 계속 진행합니다.

| 점검 항목 | 초기 결과 | 판정 |
|---|---|---|
| 768·900·1024px 팝업 기하 | 개발 서버의 React 루트 미마운트로 미측정 | 보류 |
| 오늘 하루 보지 않기 새로고침 지속성 | 팝업 미마운트로 상호작용 불가 | 보류 |
| 소스 저장 방식 | `localStorage`의 날짜 키 비교·저장 구조 확인 | 대체 실제 검증 필요 |

## 보정 전 로컬 프로덕션 측정

| 뷰포트 | 팝업 크기 | 상·하 여백 | 제어 영역 | 판정 |
|---|---:|---:|---:|---|
| 768×1024 | 721×900.8px | 각 61.6px | 내부 좌상단 238×52px | 이미지는 아직 로드되지 않아 어두운 빈 surface로 보이며, 높이는 큰 편 |
| 900×1024 | 853×1,065.8px | 각 -20.9px | 내부 좌상단 238×52px | 세로 overflow 발생 |
| 1024×1024 | 960×1,199.5px | 각 -87.8px | 내부 좌상단 238×52px | 세로 overflow 발생 |

위 결과는 이미지 컨테이너가 모바일 종횡비를 유지하던 보정 전 상태이며, 아래 최종 측정으로 대체합니다.

## 최종 태블릿 재측정

팝업은 768px부터 실제 desktop asset의 1370:748 종횡비를 사용하도록 고정했고, 768~1023px 구간은 최대 720px 폭, 1024px 이상은 최대 960px 폭으로 제한했습니다. 또한 하단 제어 행은 태블릿에서도 팝업 내부 우측 하단에 유지됩니다.

| 뷰포트 | 다이얼로그 크기 | 상·하 여백 | 하단 제어 | 가로 넘침 | 판정 |
|---|---:|---:|---:|---:|---|
| 768×1024 | 720×394px | 315px / 315px | 우측 하단 238×52px | 없음 (753px = clientWidth) | 통과 |
| 900×1024 | 720×394px | 315px / 315px | 우측 하단 238×52px | 없음 (885px = clientWidth) | 통과 |
| 1024×1024 | 960×525px | 249px / 249px | 우측 하단 238×52px | 없음 (1009px = clientWidth) | 통과 |

이미지 컨테이너는 desktop asset의 실제 비율을 사용합니다. 클라이언트 번들 단독 검사에서는 `/manus-storage/` 프록시가 제공되지 않아 이미지 natural size는 0으로 기록되지만, 별도 응답 점검에서 원본 desktop JPEG(1370×748px, 408,173B)의 정상 응답을 확인했습니다.

`오늘 하루 보지 않기`는 체크한 뒤 닫을 때 `localStorage`에 당일 날짜(`2026-09-05`)를 저장하고, 실제 새로고침 뒤에도 같은 키가 유지되어 팝업이 다시 렌더되지 않았습니다.
