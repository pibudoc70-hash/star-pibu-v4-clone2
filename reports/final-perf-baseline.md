# 새 이미지 적용 후 최종 성능 기준선

## 1. 측정 범위와 도구 상태

요청에 따라 새 이미지 참조가 포함된 로컬 프로덕션 빌드를 먼저 시도했습니다.

| 항목 | 결과 |
|---|---|
| Lighthouse CLI | 설치되어 있지 않음 |
| `pnpm exec lighthouse` | 명령을 찾을 수 없음 |
| `pnpm build` | Vite 변환 중 sandbox 고메모리 압박으로 exit 143 종료 |
| 새 `pnpm start` | 최신 빌드가 생성되지 않아 실행하지 않음 |

따라서 요청에서 허용한 대체 측정 방식으로, 실제 `star-pibu.com`의 새 `/manus-storage/` 이미지 11개에 대해 리디렉션 뒤 최종 HTTP 응답의 전송 크기를 측정했습니다. 이 결과는 **이미지 전송량만**을 나타내며 전체 홈 성능 점수나 Core Web Vitals를 대신하지 않습니다.

## 3. 새 이미지 응답 확인

현재 참조 중인 최적화 WebP 11개를 `curl -sIL`로 확인했습니다.

| 확인 항목 | 결과 |
|---|---|
| URL 수 | 11 |
| 최종 HTTP 200 | 11 / 11 |
| 응답 형식 | `image/webp` 11 / 11 |
| 합계 `Content-Length` | 219,586 B (214.4 KiB) |

## 4. 이미지 관련 감사 변화

이전의 대형 이미지 목록에서 Step 5와 Step 6의 대상 11개는 모두 새 WebP로 참조가 교체됐습니다. 각 새 파일은 200KB 이하이며, 원본 삭제 없이 별도 키로 보관됩니다. 병렬 래스터 비교에서 눈에 띄는 열화는 관찰되지 않았습니다.

Lighthouse의 `uses-optimized-images`, `uses-responsive-images`, `offscreen-images`, `modern-image-formats` 감사 수치는 이번 환경에서 생성할 수 없었습니다. 현재 대상은 이미 WebP였고, 이번 작업은 품질·표시 해상도 최적화입니다. `srcset` 도입은 사용자 지시에 따라 보류입니다.
