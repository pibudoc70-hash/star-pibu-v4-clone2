환자 상담 이미지는 데스크톱에서 561×560 CSS px로 표시되지만 원본이 1001×666 px로 이미 2배 렌더 크기보다 작습니다. 해상도를 인위적으로 키우지 않고 quality 78 재압축만 적용했습니다.

## 3. 시각 비교

원본(좌측)과 최적화본(우측)을 같은 크기로 나란히 비교했습니다. 대기실·상담실·외관·시술실의 설비 윤곽, 벽면 텍스트, 인물·유니폼 경계에 눈에 띄는 열화가 없었고, 환자 상담 이미지의 인물·로고·배경도 유지되었습니다. 비교본은 `/home/ubuntu/webdev-static-assets/step5-comparison-before-after.webp`에 저장했습니다.

원본 공개 페이지와 개발 페이지의 같은 1280px 캡처를 시도했습니다. 공개 페이지는 anchor scroll 전에 히어로가 캡처됐고, 개발 페이지는 초기 로딩 레이어가 캡처됐습니다. 개발 서버를 재시작하고 12초 이상의 해제 대기 후에도 비교 캡처 프로세스가 응답하지 않았으며, 프로젝트 스크린샷 캡처도 실패했습니다. 따라서 이 두 캡처는 시설 레이아웃 비교 근거로 사용하지 않습니다.

대신 원본과 최적화본을 동일 픽셀 크기로 정규화한 5행 병렬 래스터 비교(좌측 원본·우측 최적화본)를 수행했습니다. 시설 장비 윤곽·벽면 텍스트·인물과 유니폼 경계·고대비 로고에서 눈에 띄는 열화는 없었습니다. 또한 새 스토리지 URL 5건은 모두 HTTP 200으로 직접 확인했고, `FacilitySection.assetRecovery.test.ts`와 `PhilosophySection.patientConsultation.test.ts`가 새 URL 참조를 보호합니다.
