## 요약

이번 작업은 디자인을 전면 재구성하지 않고, 실제 사용자에게 보이는 오류·일관성·접근성·검색 노출·관리 편의성 문제를 **작은 변경 단위**로 보완했습니다. 각 단계는 시작 전에 롤백 기준점을 저장하고, 수정 후 타입 검사·정적 검사·회귀 테스트·프로덕션 빌드·미리보기 또는 운영 화면 확인을 거쳤습니다.

가장 중요한 결과는 Directions 지도 실패 시 빈 회색 영역을 남기지 않는 대체 UI, 시술 상세의 안정적인 초기 로딩 화면, 다국어 위치 정보 통일, 시술 상세 구조화 데이터 식별자 정합화, 관리자 FAQ 입력 안전장치, 그리고 의존성 감사 취약점 해소입니다.

## 추가 안정화 작업

최종 감사에서 PostCSS 하위의 `nanoid` 3.3.17 취약 의존성이 발견되어, workspace override로 **3.3.18**을 고정하고 lockfile을 갱신했습니다. 이후 frozen lockfile 설치와 의존성 감사를 재실행해 moderate 이상 알려진 취약점이 없는 상태를 확인했습니다.

Directions 지도는 단순히 `tilesloaded` 이벤트가 발생했다고 성공으로 보지 않도록 수정했습니다. 지도 컨테이너 안에 실제 `.gm-style` 타일 또는 canvas DOM이 생성된 경우에만 성공으로 처리합니다. 따라서 이벤트만 발생하고 화면이 비는 환경에서는 8초 후 명시적인 외부 지도 대체 UI가 나타납니다.

## 운영상 확인된 제한 및 보류 사항

운영 도메인은 프리렌더 본문과 JSON-LD를 정상 제공합니다. 다만 서버 코드에서 설정한 공유 캐시 정책과 달리, 최종 응답의 `Cache-Control`은 호스팅 계층에서 `no-cache, no-store, must-revalidate`로 유지됩니다. 이는 사이트 코드가 아닌 배포·호스팅 계층의 응답 헤더 정책 범위입니다. 기능·SEO 원본 HTML 노출에는 문제가 없지만, CDN 공유 캐시 성능 효과는 현재 운영 헤더 기준으로 적용되지 않습니다.

GitHub 원격 백업은 코드 문제와 무관하게 인증 권한이 거부되어 보류 상태입니다. 로컬 main과 운영 체크포인트는 보존되어 있으며, 권한이 준비된 뒤 force push 없이 일반 push로 동기화해야 합니다.
