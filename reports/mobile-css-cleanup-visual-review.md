# CSS 정리 후 모바일 시각 검토

## 1차 캡처 관찰

390×844px Chromium 캡처에서 홈과 시술·장비 목록의 상단 상태를 확인했다. 홈은 프로모션 팝업이 의도한 오버레이 위에 완전히 표시되고, 이미지·당일 숨김 제어·닫기 제어가 서로 겹치지 않았다. 시술·장비 목록은 헤더, 제목, 설명, 다크모드 제어와 두 열 카테고리 버튼이 viewport 안에 있으며 텍스트 잘림이나 가로 넘침은 관찰되지 않았다.

이 캡처는 공용 preview의 비공개 안내 바를 함께 포함한다. 해당 바는 배포 앱 UI가 아니므로 레이아웃 결함으로 판정하지 않는다. 이어서 시술 상세·예약·소개·의료진·오시는 길·이벤트 화면과 접힌/열린 상호작용 상태를 확인한다.

## 2차 캡처 관찰

`/treatments/ulthera`의 모바일 첫 화면은 긴 한글 H1이 자연스럽게 여러 줄로 줄바꿈되고, 배지·설명·시술 소개가 잘리지 않았다. 390px 화면폭의 가로 넘침도 보이지 않았다.

검토 목록에 넣은 `/reserve`는 현행 공개 라우트가 아니어서 영문 404 페이지가 표시됐다. 이는 CSS 정리로 인해 발생한 layout 결함으로 판정하지 않으며, 실제 예약 흐름을 변경하지 않는다. 다음 검토에서는 앱이 등록한 실제 예약 route를 찾아 해당 화면을 확인한다.

## 3차 캡처 관찰

`/about`은 390px에서 긴 소개 문단과 수치 카드 3개를 viewport 안에 정렬했고, 텍스트 겹침·clipping·가로 넘침이 없었다. `/doctors`도 제목, 소개 문장, 의료진 선택 control, 대표 이미지가 동일 폭 안에 정상 배치됐다. 두 화면 모두 CSS 정리에서 제거한 review·brand-card·philosophy statistic legacy class에 의존하지 않는 현행 컴포넌트 레이아웃을 확인했다.

## 4차 캡처 관찰

`/directions`은 390px에서 헤더·타이틀·지도·주소 섹션이 정상 흐름으로 연결되며 지도나 연락처 카드의 clipping 및 가로 overflow가 없었다. `/events` 역시 현행 공개 라우트가 아니므로 404가 표시됐다. 이벤트는 홈페이지의 Special Event 섹션과 개별 event detail route로 제공되는 구조이므로, 404를 CSS 정리 회귀로 간주하지 않았다.

## 5차 캡처 관찰: 홈페이지 스크롤 구간

팝업을 닫은 뒤 캡처한 홈 900px 지점에서 소개 문단, 배너, Special Event 헤더와 이벤트 안내 카드의 폭·여백·문장 줄바꿈은 정상이었다. 2,100px 지점에서도 이벤트 행의 이름·가격·expand control은 오른쪽 기준으로 정렬되어 있고, 통증관리 이정표 및 다음 의료진 섹션이 침범·겹침 없이 이어졌다. CSS 정리 후 mobile event/통증관리 경로의 layout 깨짐은 관찰되지 않았다.

## 6차 캡처 관찰: 시술 상세 스크롤 구간

`/treatments/ulthera`의 중간 구간은 동영상 카드·주의사항 패널·FAQ 제목이 390px 폭 안에 유지됐다. FAQ 하단 구간도 긴 질문이 자연스러운 여러 줄로 표시되며, `더보기` control은 text와 분리되어 잘리지 않았다. 자세한 문장은 의도한 line clamp 상태로 유지돼 CSS 정리로 인한 card border·spacing·overflow 회귀는 관찰되지 않았다.

## 7차 캡처 관찰: 장비 목록 및 소개 중간 구간

`/equipment3`의 대표 카드들은 이미지, 제목, 요약, 시술 시간·회복 정보, 자세히 보기 링크를 390px 너비에 맞게 표시했다. 두 카드 모두 경계선·내부 여백·이미지 비율이 일관되고 오른쪽 clipping이 없었다. `/about`의 가치 문구 및 시설 사진도 헤더 아래에서 정상 순서로 흐르며, responsive text와 이미지의 겹침·overflow가 없었다.

## 8차 캡처 관찰: 오시는 길 및 공지 목록

`/directions`의 주소·전화·진료시간 카드와 카카오맵/네이버지도 열기 control은 390px에서 안전하게 줄바꿈되고 버튼 폭·간격이 유지된다. `/notice`의 썸네일, 긴 제목의 말줄임, 날짜·조회 정보와 행 이동 chevron도 한 줄 레이아웃 안에서 충돌하지 않았다. 두 화면에서 고정 헤더 및 공용 preview 안내 바를 제외한 앱 콘텐츠의 viewport overflow나 겹침은 관찰되지 않았다.

## 9차 캡처 관찰: 375px 좁은 모바일 폭

375px에서도 홈 이벤트의 가격·expand control과 통증관리 이정표가 한 행/허용된 두 줄 안에서 균형 있게 유지됐다. `equipment3`의 대표 카드 역시 이미지·긴 제목·요약·메타 정보·자세히 보기 링크가 clipping 없이 이어졌다. 390px과 375px 표본 모두에서 CSS 정리 후 모바일 카테고리, 이벤트, 카드 레이아웃의 가로 깨짐은 관찰되지 않았다.

## 10차 캡처 관찰: 상호작용 상태

390px에서 열린 모바일 메뉴는 44px 닫기 control, 메뉴 행, chevron, 언어 선택 영역을 viewport 안에 유지했으며 overlay와 하단 preview 안내 바 외의 의도하지 않은 overlap은 보이지 않았다. 홈페이지 2,200px 위치의 DOM에는 통증관리 disclosure 대신 의료진 carousel이 있어 해당 위치에서 disclosure를 열 수 없었다. 이 관찰은 CSS 회귀가 아니라 현행 homepage 구성/scroll target 차이이며, 앞선 통증관리 이정표 캡처에서는 정상 폭과 줄바꿈을 이미 확인했다.

시술 상세 FAQ의 `더보기`를 연 상태에서도 긴 답변은 card 안에서 자연스럽게 확장됐고 접기 control도 정상 위치에 표시됐다. 제목·답변·버튼 사이의 겹침이나 가로 스크롤은 없었다.

| 카드·이벤트 가격·CTA·FAQ expansion | 정상 표시 |

공용 preview 하단의 “This page is not live …” 안내 바는 Manus 검토 환경 UI이며 배포 페이지의 고정 CTA가 아니다. 또한 `/reserve`, `/events`는 현행 canonical route가 아니어서 404가 표시됐으며, 예약·이벤트 흐름을 수정하지 않았다. CSS cleanup에서 제거한 legacy selector와 현행 mobile layout 사이의 회귀는 이번 표본에서 발견되지 않았다.
