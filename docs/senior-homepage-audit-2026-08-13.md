# 스타피부과 홈페이지 재감사 보고서

**작성일:** 2026-08-13  
**대상:** `https://star-pibu.com` 및 현행 소스 (`10bdb472`)  
**범위:** 공개 홈페이지·시술 상세·Directions·다국어·SEO/성능/접근성·관리자 FAQ 유지보수성  
**제외:** 내부 예약·OTP·예약 관리자·예약 알림·예약 DB 및 `reservation`/`booking`/`otp` 명명 코드. 모든 신규·수정 전환은 기존 **네이버 예약과 카카오 상담 외부 링크**를 그대로 유지한다.

## 결론

현재 사이트는 홈과 대표 시술 상세에서 주요 본문, FAQ, 외부 네이버·카카오 전환 동선, 이미지 대체 텍스트, 프리렌더 SEO 기반을 갖추고 있다. 그러나 실제 운영 화면에서 **Directions 지도가 모든 언어에 걸쳐 빈 회색 영역으로 표시되는 문제**가 재현되었다. 이는 방문 전환의 마지막 단계인 위치 확인을 방해하므로, 디자인 개선보다 먼저 작은 범위로 복구해야 한다.

이외에는 기능을 바꾸기보다 응답 지연, 주소 안내의 상충, 상세 페이지의 초기 공백형 로딩, 마크업 접근성 경고, 구조화 데이터의 중복 가능성을 순서대로 정리하는 것이 안전하다. 이번 감사는 기존 예약·OTP 기능을 분석 또는 수정 대상으로 삼지 않았으며, 보고서의 모든 제안은 공개 화면과 공통 컴포넌트에 한정한다.

## 디자인·사용자 경험 진단

홈의 히어로, 전문의 소개, 시술 탐색, 이벤트, FAQ, 위치 정보의 흐름은 설득 구조를 갖추고 있으며, 첫 화면의 상담·예약 링크도 명확하다. 따라서 새로운 섹션이나 색상 변경보다 **사용자가 실제로 길을 확인하고 상세 정보를 기다리는 순간**을 다듬는 편이 효과 대비 위험이 낮다. 특히 Directions는 헤더·정보 카드·길찾기 버튼이 잘 정리돼 있지만, 핵심 지도만 실패하므로 레이아웃 재설계 없이 지도 로드와 실패 대체 UI만 정확히 고치는 것이 적절하다.

시술 상세는 FAQ와 가이드 영상까지 이어지는 신뢰 정보가 충분하다. 다만 최초의 전체 화면 로더는 내용이 아직 준비되지 않은 페이지처럼 보이게 한다. 동일한 여백과 정보 카드 모양의 스켈레톤을 사용하면 시각적 안정성을 유지한 채 대기 체감을 줄일 수 있다. 로딩 성능은 한 번의 서버 측 측정만으로 결론내릴 수 없지만, 반복 측정에서 28초 응답이 한 번 발생했으므로 프리렌더 HTML의 무조건 재검증 정책과 데이터 경로를 우선 계측해야 한다. Google은 좋은 사용자 경험을 위해 LCP 2.5초 이내, INP 200ms 미만, CLS 0.1 미만을 권고한다.[1]

## 프런트엔드·백엔드 안정성 진단

현행 프리렌더는 검색·AI 크롤러가 읽을 본문과 JSON-LD를 제공하는 장점이 있다. 하지만 홈과 장비 상세 프리렌더 모두 `no-cache, must-revalidate`를 설정하고 있어 서버 응답 비용을 매 요청에 다시 지불할 수 있다. 캐시 변경은 색인 본문이 낡아질 위험이 있으므로, 적용 전에 DB 수정·관리자 저장 시 캐시 무효화 전략과 운영 응답 헤더를 함께 테스트해야 한다. 이 작업은 예약·OTP와 독립적이다.

접근성은 lint 오류 0건을 유지하고 있지만, 경고 191건을 장기적으로 두면 실제 회귀를 식별하기 어렵다. 우선 예약 관련 파일은 제외하고 Directions의 중첩 인터랙티브 요소, 공지 관리의 포인터 전용 동작, 공개 컴포넌트의 label 연결부터 작은 단위로 해결해야 한다. 모든 동작은 키보드로 수행할 수 있어야 한다는 WCAG 기준과도 일치한다.[2]

## 권장 실행 순서

첫 번째 변경은 Directions 지도 복구다. 개발 환경과 운영 환경에서 한국어·영어·일본어·중국어·번체 중국어의 지도 표시, 길찾기 외부 링크, 주소 복사, 키보드 탭 순서를 모두 확인하고 체크포인트를 저장한다. 지도 제공자가 다시 실패해도 빈 박스가 아닌 안내·외부 지도 링크가 남는 상태를 성공 기준으로 삼는다.

두 번째 변경은 위치 정보 단일화와 상세 로딩 스켈레톤이다. 이 단계는 콘텐츠 확정 값을 먼저 확인한 뒤 공통 데이터만 교체하며, 예약 CTA의 링크와 명칭은 수정하지 않는다. 세 번째 단계에서 성능 계측·캐시 정책·구조화 데이터 중복을 테스트 기반으로 다룬다. 마지막으로 비예약 접근성 경고와 관리자 FAQ 검증 UX를 작은 PR 단위로 정리한다.

> **의료 콘텐츠 경계:** 시술 효과, 회복, 지속 기간, 마취 옵션, 전문의 자격 및 사례 수는 디자인 문구가 아니라 의료·운영 사실입니다. 문구의 신설·번역·변경은 원장 또는 지정 담당자의 승인 후에만 반영해야 하며, 데이터에 없는 외국어 번역을 코드 fallback으로 생성해서는 안 됩니다.
